# 拍照导入设计（Photo Import）

状态：草案，待评审。范围：只写设计，不含代码。

> 注意：`docs/DEV_PLAN.md` 里"拍照识题"编号是 P4，本文按需求叫 P3 拍照导入。编号以评审结论为准。

## 1. 目标与范围

**目标**：用户拍一张纸质数独（或从相册选图），App 在手机上识别出题面，确认后变成一道可玩的题。

**范围内**
- 支持 4×4、5×5、9×9，与 `BoardPreset` 的三种棋盘一致。
- 印刷体数字为主。手写体尽力而为，不承诺准确率。
- 识别结果先进入"确认页"，用户改完再导入，不直接开局。
- 全部在设备上完成，不联网。

**范围外（v1 不做）**
- 手写体高准确率、斜拍极端角度、多题同图。
- 自动判断宫线形状（见第 4 节）。
- 6×6 等新尺寸（`Rules.supportedSizes` 目前只有 `[4, 5, 9]`）。

## 2. 识别流程

```
照片 (CGImage)
  → 找棋盘外框      VNDetectRectanglesRequest
  → 透视校正        CIPerspectiveCorrection（得到正方形图）
  → 按边长切格      size × size 张小图（每边留约 8% 边距，去掉格线）
  → 逐格识别数字    VNRecognizeTextRequest
  → 组装            RecognitionResult → Grid（题面 givens）
  → 确认页          低置信度格高亮，用户修改
  → 导入            生成 SamplePuzzle / BoardViewModel
```

### 2.1 找外框
- `VNDetectRectanglesRequest`：要求长宽比接近 1（`minimumAspectRatio` 约 0.8），取面积最大的候选。
- 没找到就报错，不猜（见第 6 节）。

### 2.2 透视校正
- 用四个角点调 `CIPerspectiveCorrection`，输出固定边长（如 900×900 像素）的正方形，方便后面均匀切格。

### 2.3 切格
- 边长 `n`（4/5/9）决定切成 `n × n` 块。每块四周裁掉一点，避免格线被当成数字（比如把线读成"1"）。

### 2.4 逐格识别
- 每块单独调 `VNRecognizeTextRequest`（`recognitionLevel = .accurate`，关闭语言纠错 `usesLanguageCorrection = false`）。
- **只认数字**：结果里只保留字符 `1...n`。读到 `0`、字母、多个字符都当"不认识"。
  - 4×4 只收 1–4；5×5 只收 1–5；9×9 只收 1–9。
- **置信度阈值**：`confidence >= 0.8` 视为可信；`0.5..<0.8` 标成"低置信度"；低于 0.5 当作没读到。阈值先定，之后用样本调。
- **空格判断**（两步，先便宜后贵）：
  1. 墨迹比例：块里深色像素占比 < 约 2%，直接判空，不调 Vision（也更快）。
  2. 有墨迹但 Vision 没读出数字：标成"低置信度的未知格"，交给用户确认，不默认当空。

### 2.5 组装成 App 的 `Grid`
- 用现有 `Grid.init(size:cells:)`（会校验长度和 0...size），空格写 `Grid.emptyCell`（0）。
- 低置信度的格子先放识别到的最佳值（没有就 0），同时在 `RecognitionResult` 里记下来，不进 `Grid`。
- 导入时 `givens` 就是确认后的 `Grid`；`BoardViewModel` 会用 `Self.givenIndexes(in:)` 把非 0 格当题目给定数字。

## 3. 尺寸：检测还是用户选？

**推荐：用户选尺寸，App 给一个猜测当默认值。**

- 猜测方法：校正后看格线数量（或用 2.3 切格后各尺寸的墨迹对齐程度打分），选得分最高的尺寸。
- 为什么不全自动：4×4 与 5×5 线条很像；9×9 里大量空格会让格线检测不稳；猜错后用户完全不知道。
- 界面上复用现有的 `SizePickerView` / `BoardPreset`，选完立刻重新切格识别，成本很低。

## 4. 5×5 与宫的布局

仓库现状：**5×5 是拉丁方，没有宫**（`Rules.fiveByFive` 的 `boxRows` / `boxCols` 都是 nil，`BoardPreset.five.detail` 写的是"拉丁方，无宫"）。所以 v1 没有"不规则宫"要识别：

| 尺寸 | 宫来源 |
|------|--------|
| 4×4 | `Rules.fourByFour`（2×2） |
| 5×5 | `Rules.fiveByFive`（无宫） |
| 9×9 | `Rules.nineByNine`（3×3） |

- 规则一律由 `BoardPreset.rules` 给出，**不从照片推断**宫线。照片只提供数字。
- 如果以后要支持不规则宫（如 5×5 五个连通区域）：照片里很难可靠识别粗线形状，v1 不做；需要的话由用户在确认页手动涂区域，并且要先扩展 `Rules`（它是冻结接口，需单独评审）。

## 5. 隐私

- 全程设备端。不联网、不上传、不存照片：图片只在内存里处理，导入完成或取消就释放。
- 只读取用户主动选的那一张（相册用 `PhotosPicker`，不要求整库权限；相机拍照才要权限）。
- `Info.plist` 文案（中文）：
  - `NSCameraUsageDescription`：`用于拍摄纸质数独题目并在本机识别，照片不会被保存或上传。`
  - `NSPhotoLibraryUsageDescription`：`用于读取你选择的数独照片并在本机识别，照片不会被保存或上传。`
- 测试图片只放合成样本或自己拍的题，**不提交用户照片**（见 `Tests/ocr-samples/README.md`）。

## 6. 错误情况

| 情况 | 处理 |
|------|------|
| 没找到外框 | 提示"没找到棋盘，请让整张棋盘入镜"，可重选 / 重拍 |
| 倾斜太大 / 光线暗 / 模糊 | 找到框但低置信度格太多（如超过 30%）时提示"照片不清楚，建议重拍"，仍允许继续手改 |
| 尺寸选错 | 确认页可改尺寸，改后重新切格；识别出大于边长的数字（如 4×4 里读到 7）会标红 |
| 不认识的数字 | 该格标成"待确认"，导入按钮在全部处理前给出提示，但不强制 |
| 导入后有冲突 | 用 `SudokuBoardEngine.conflicts(in:rules:)`（默认 `EngineBoardAdapter`）算出冲突格，在确认页标红；用户可改，也可强制导入 |
| 无解 / 多解 | `solutionCount(_:rules:limit: 2)` 返回 0 提示"这题无解，请检查数字"；返回 2 提示"这题有多个解"，仍允许导入 |
| 用户取消授权 | 显示说明和"去设置"入口；相册走 `PhotosPicker` 不受影响 |

## 7. PR 拆分（每个 ≤400 行）

### PR A：纯逻辑层（不依赖相机，可单测）
- 切格：输入已校正的方图 + 边长，输出 `n × n` 块（`CellSlicer`）。
- 单格判空：墨迹比例（`InkDetector`）。
- 识别结果 → `Grid` 的组装（`GridAssembler`）：数字范围过滤、置信度分级、输出 `RecognitionResult`（含每格置信度）。
- 把 Vision 调用藏在协议后面（如 `CellTextRecognizer`），测试里用假实现，真实实现随 PR 一起给一个薄封装。
- 单元测试 + 随包的测试图片（合成的 4×4 / 5×5 / 9×9 方图，放 `Tests/ocr-samples/`）。
- 代码位置：`Packages/BoardVision`（README 已占位）放切格和识别；`Grid` 在 App 里定义，所以"结果 → App `Grid`"那一步放 `SudokuApp/Features/Camera/`（见开放问题 1）。

### PR B：入口 + 确认页
- 相册（`PhotosPicker`）和相机入口；外框检测与透视校正（需要真图）。
- 确认页（SwiftUI）：显示 `n × n` 网格，低置信度格高亮，点格用 `NumberPadView` 改值，显示冲突/无解提示。
- `Info.plist` 两条中文权限文案。
- 导入后进入 `BoardScreen`（新建 `BoardViewModel(title:puzzle:)`）。

## 8. 测试策略

- **PR A 单元测试（不需要相机）**
  - 切格：已知方图 → 块数、块尺寸、边距正确。
  - 判空：纯白块 → 空；有数字的块 → 非空。
  - 组装：假识别器返回固定结果，覆盖：范围外数字被丢弃、低置信度被标记、长度错误抛 `Grid.ValidationError`。
  - 样本图：每种尺寸至少 1 张清晰图，期望 `Grid` 与 `FixtureLibrary` 里的题面逐格相等。
- **PR B**：外框检测用 2–3 张真实照片（自拍样本）做冒烟测试；确认页用 SwiftUI 预览 + 少量视图模型测试（改格、冲突提示）。
- **验收指标**：沿用视觉角色文档：印刷体格级准确率 ≥98%，整盘识别 <1s。
- 手写体不进验收指标，单独记录结果。

## 9. 开放问题

1. 模块位置：切格和识别放 `Packages/BoardVision`，而 `Grid` 在 App 里；是让包自己定义轻量结果类型，再由 App 转 `Grid`，还是把 `Grid` 挪进共享包？
2. 编号：本文叫 P3，`DEV_PLAN.md` 叫 P4，要不要统一？
3. 手写体要不要支持？若要，`VNRecognizeTextRequest` 可能不够，需评估小型 Core ML 数字模型（体积、训练数据）。
4. 低置信度阈值（0.8 / 0.5）和墨迹比例（2%）暂定，需要用真实样本调；样本从哪来、放多少张？
5. 最低系统版本：`VNRecognizeTextRequest` 与 `PhotosPicker` 对 iOS 版本有要求，需对照 `docs/adr/0002-ios-deployment-target.md` 确认。
6. 导入时若题目有冲突，是只警告还是禁止导入？当前倾向"警告 + 允许"。
7. 多解题要不要允许导入？当前倾向允许并提示。
8. 将来是否做不规则宫（需扩展冻结的 `Rules`）？v1 明确不做，路线图里要不要留位置？

## 总结

- 流程：找框 → 透视校正 → 切格 → 逐格读数字 → 组装 `Grid` → 用户确认，全程在设备上。
- 尺寸由用户选（App 给默认猜测）；5×5 在仓库里是无宫拉丁方，宫规则来自 `BoardPreset.rules`，不从照片推断。
- 分两个 PR：A 是可单测的纯逻辑，B 是相机/相册入口加确认页；隐私上只读不存不传。
