# 开发约定

## 语言
- **代码使用英文**：变量、函数、类型、文件名、分支名。提交信息可用英文。
- **注释和文档使用中文**。

## 代码风格
- 优先简单、稳定的逻辑；能用直白写法就不用技巧性写法。
- **不做过早抽象**：同样的逻辑出现第三次再考虑提取；不为“将来可能”加扩展点。
- 优先值类型和纯函数；避免全局可变状态。
- 不随意引入第三方依赖，引入前需 Ari 同意。
- 禁止强制解包（测试除外）；错误要处理或明确上抛。
- 遵守 SwiftLint 规则，零警告。
- 单个函数尽量 < 40 行，单个文件尽量 < 400 行。

## 界面
- 页面友好：操作有反馈、错误有明确提示、支持深色模式和动态字体。
- 响应迅速：耗时操作不放主线程。

## 分支与提交
- 分支：`feat/<module>-<desc>`、`fix/<module>-<desc>`。
- 一个 PR 只做一件事，尽量 < 400 行改动。
- 提交信息示例：`engine: add hidden single technique`。

## 测试
- 引擎、图层、计步逻辑必须有单元测试；新增技巧必须附测试题。
- 修 bug 先写能复现的测试。
- 测试不得依赖网络或随机性（随机需固定种子）。

## 审查
- **作者不得审查自己的代码。**
- 合并条件：CI 全绿 + 1 位非作者审查通过 + Ari 确认。
- 审查意见分“必须改”和“建议”。

## 模块所有权
同一时间每个模块只有一个负责人，跨模块改动先找 Ari 协调。

## 文档与日报
- 接口变更先更新文档再改代码。
- 每个 AI 每个工作日写日报，见 `daily-reports/README.md`。
