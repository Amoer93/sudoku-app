# 开发计划

按中型公司节奏推进：**小步迭代，每个 Sprint 1–2 周，同一时间最多 1–2 个阶段处于进行中**。每个阶段必须通过“审查/测试闸门”后，下一阶段才全面开工（下一阶段只允许提前做设计和调研）。

## 通用规则
- 每个 Sprint 开始时由 Ari 发任务卡，结束时开评审会（文字形式）并更新本计划。
- 单个任务卡尽量控制在 1–3 天工作量，一个 PR 只做一件事。
- 阶段闸门：CI 全绿 + 非作者审查通过 + 测试工程师验收报告 + Ari 签字。
- 进度落后时优先砍范围，不压缩测试和审查。

## 里程碑总览
| 阶段 | 内容 | 预计 Sprint | 里程碑 |
|---|---|---|---|
| P0 | 项目搭建 / CI / 规范 | 1 | M0 仓库可构建 |
| P1 | 核心引擎 + 手动输入棋盘 | 2–3 | M1 能手动玩并自动解题 |
| P2 | 逻辑提示 + 假设图层 | 2–3 | M2 核心卖点可用 |
| P3 | 题库 + 本地最佳记录 | 2 | M3 离线完整可玩（内测 TestFlight） |
| P4 | 拍照识题 | 2–3 | M4 拍照导入 |
| P5 | 在线排行榜 / 后端 | 2 | M5 联网功能 |
| P6 | 打磨、性能、无障碍、上架 | 2 | M6 提交 App Store |

并行关系：P1 与 P0 尾部可重叠；P4 的调研可在 P2/P3 期间进行；P5 可与 P4 后半段重叠。

---

## P0 项目搭建 / CI / 规范（1 Sprint）
**目标**：仓库结构、构建、CI、规范就位。
| 任务 | 负责角色 |
|---|---|
| 建立仓库与目录结构（见 TECH_DESIGN） | 总工程师 |
| Xcode 工程、SwiftUI 空壳、SudokuEngine Swift Package | iOS 开发 |
| SwiftLint/SwiftFormat、GitHub Actions（构建+测试+Lint） | 代码审查 |
| 测试目标与示例测试、测试报告模板 | 测试（D 兼任） |
| 规范文档与 PR 模板 | 总工程师 |
**依赖**：无。
**退出标准**：`main` 可构建，CI 每次 PR 自动运行，规范文档已确认。
**闸门**：审查 CI 配置；空工程跑通测试。

## P1 核心引擎 + 最小棋盘 UI（2–3 Sprint）
**目标**：9×9、4×4、5×5（拉丁方）规则可配置，求解、合法性校验；手动输入可玩。
| 任务 | 负责角色 |
|---|---|
| Rules / Grid 数据模型 | 算法 |
| 合法性校验（冲突检测） | 算法 |
| 求解器（约束传播 + 回溯）、唯一解检测 | 算法 |
| 棋盘渲染（按规则显示宫线）、数字输入、冲突高亮、撤销 | iOS 开发 |
| 引擎批量正确性测试（已知题集） | 测试 |
**依赖**：P0。UI 可先用假数据，接口冻结后再接引擎。
**退出标准**：三种尺寸可手动输入、自动解题；9×9 求解 <50ms。
**闸门**：引擎代码由 A 审查；UI 代码由 C 审查；测试报告通过。

## P2 逻辑提示 + 假设图层（2–3 Sprint）
**目标**：只对确定格给提示并说明技巧；无确定格时推荐最佳假设格；多层半透明假设图层。
| 任务 | 负责角色 |
|---|---|
| 基础技巧：唯余、隐性唯一 | 算法 |
| 进阶技巧：区块排除、数对（按需再加） | 算法 |
| 最佳假设格评分 | 算法 |
| 图层数据模型与 UI（新建、叠加、撤销、确认、放弃） | iOS 开发 |
| 提示展示 UI（高亮依据格、技巧说明） | iOS 开发 |
| 提示正确性大规模测试、图层状态测试 | 测试 |
**依赖**：P1 引擎接口稳定。
**退出标准**：提示零错误；图层最多支持 5 层以上无卡顿。
**闸门**：同 P1，另需 Ari 体验验收。

## P3 题库 + 本地最佳记录（2 Sprint）
**目标**：内置题库（各尺寸/难度），步数与用时记录，本地最佳。
| 任务 | 负责角色 |
|---|---|
| 生成脚本 + 难度评级，产出首批题库（JSON） | 后端与题库（评级逻辑由算法提供） |
| 题库加载与选择界面 | iOS 开发 |
| 步数/用时统计口径与本地存储 | iOS 开发 |
| 题库唯一解抽检、记录逻辑测试 | 测试 |
**依赖**：P1、P2 的评级。
**退出标准**：离线完整可玩；发布 TestFlight 内测。
**闸门**：审查 + 测试 + 内测反馈无 P0 问题。

## P4 拍照识题（2–3 Sprint）
**目标**：拍照/相册导入，识别尺寸和数字，低置信度格可修正。
| 任务 | 负责角色 |
|---|---|
| 棋盘检测与透视校正 | 视觉识别 |
| 尺寸判定、数字识别 | 视觉识别 |
| 拍照入口与修正界面 | iOS 开发 |
| OCR 样本集与准确率测试 | 测试 |
**依赖**：P1；调研可提前。
**退出标准**：印刷体格级准确率 ≥98%，识别 <1s。
**闸门**：C 审查（A 是作者）；准确率报告。

## P5 在线排行榜 / 后端（2 Sprint）
**目标**：题库在线更新、按步数排行（同步数比用时）、防作弊校验。
| 任务 | 负责角色 |
|---|---|
| API 与服务、Sign in with Apple / Game Center | 后端与题库 |
| 服务端步骤校验 | 后端（复用算法逻辑） |
| 题库增量更新、排行榜 UI | iOS 开发 |
| API 测试、离线/弱网测试 | 测试 |
**依赖**：P3。
**退出标准**：非法成绩被拒；断网时 App 正常可玩。
**闸门**：审查 + 安全/隐私检查。

## P6 打磨、性能、无障碍、上架（2 Sprint）
| 任务 | 负责角色 |
|---|---|
| 动画、引导、深色模式、动态字体、VoiceOver | iOS 开发 |
| 性能与内存检查、崩溃排查 | 代码审查 |
| 多机型回归 | 测试 |
| 隐私清单、截图、描述、审核说明 | iOS 开发 + 总工程师 |
| 审核指南合规检查 | 代码审查 |
**退出标准**：无 P0/P1 缺陷，提交审核。
