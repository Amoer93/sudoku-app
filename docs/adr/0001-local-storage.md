# 0001. 本地进度与设置使用 JSON 文件

## 状态

已接受（P0）

## 背景

[TECH_DESIGN.md](../TECH_DESIGN.md) 第 8 节把进度、记录、设置留在 SwiftData 和 JSON 文件之间，要求 P0 选更简单、更稳定的一个。内置题库已经定为包内 JSON。

## 决定

进度、个人记录和设置使用应用支持目录里的 JSON 文件，通过 `Codable` 读写。不使用 SwiftData。

P3 实现 `LocalStore` 时按用途分文件，例如：

- `progress.json`：进行中的对局
- `records.json`：个人最佳
- `settings.json`：设置

下载的题库仍放缓存目录，并带版本号。这一点技术设计里已经写了，本决定不改它。

## 理由

- 技术设计里的 `Rules`、`Grid`、`Move`、`Puzzle` 已经是 `Codable` 值类型，可以直接编码，不必再维护一套持久化模型。
- 这些数据量小，也不需要关系查询。
- JSON 没有 schema 迁移。文件出了问题可以直接打开看。
- 测试可以读写临时目录，不依赖模拟器里的数据库。
- 不引入额外框架，和「能不用的依赖就不用」一致。
- 和包内题库一样用 JSON，阅读和排错更直接。

## 后果

- P3 之前不要写存储代码。
- 以后如果真的出现复杂查询或大量关联数据，再单独开一份 ADR 评估是否迁移。迁移前 JSON 仍然可以当导出格式。
